# NannyCam Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browser-based nanny cam between two phones — WebRTC P2P video/audio with noise/motion alerts and talk-back, served from a Mac over Tailscale, no third party ever touching media.

**Architecture:** Vite + TypeScript + Preact multi-page client (camera page, viewer page); single Bun TS server file serving static assets and relaying WebSocket signaling with an in-memory room state machine; no STUN/TURN (host candidates only — LAN + Tailscale 100.x); heartbeat + `getStats()` watchdog on the viewer; TLS via `tailscale serve` (outside app code).

**Tech Stack:** Bun (server + unit tests), Vite, TypeScript, Preact, Playwright (E2E with fake media), `qrcode` (only runtime client dep).

**Spec:** `docs/superpowers/specs/2026-07-19-nannycam-design.md` — the authority on behavior. Read it before starting.

**Model routing (per user request):** Each task is tagged. `[mechanical]` → cheapest capable model (Haiku/Sonnet-tier subagent). `[core]` → strongest model (Fable/Opus-tier). Reviews between tasks always run on the strongest model.

```
│   │   ├── main.tsx            # Camera page app (Preact)
│   │   ├── preflight.tsx       # Checklist UI + dedicated-device toggle

│       ├── main.tsx            # Viewer page app (Preact)

├── e2e/monitor.spec.ts         # Playwright: pair → frames → kill → alarm → revive

```

Design rules locked in: `rooms.ts` and `watchdog.ts` are **pure logic with injectable time** — all safety-critical behavior is unit-testable without sockets or browsers. `shared/protocol.ts` is the single source of truth for the wire format; neither side hand-rolls message shapes.

### Task 2: Shared protocol module `[core]`

**Files:** Create `shared/protocol.ts`, `shared/protocol.test.ts`

The wire format, complete. Every WS message is validated with `parseMessage` on both ends; invalid input returns `null` (never throws — spec: hostile guest must not crash the relay).

- [ ] **Step 1: Write failing tests** — `parseMessage` accepts each valid message below and returns typed object; rejects (returns `null`) non-JSON, unknown `type`, missing fields, wrong field types, oversized payloads (> 64 KB).
- [ ] **Step 2:** Run `bun test shared/` → FAIL (module missing).
- [ ] **Step 3: Implement.** Message union (discriminated on `type`):

```ts
// Client → Server
type C2S =
  | { type: 'create-room' }                                        // camera, new room
  | { type: 'recreate-room'; code: string }                        // camera, after server restart
  | { type: 'reclaim-room'; code: string; cameraToken: string }    // camera, after own disconnect
  | { type: 'join-room'; code: string }                            // viewer
  | { type: 'stop-camera'; code: string; cameraToken: string }     // explicit teardown
  | { type: 'signal'; to: string; payload: unknown };              // SDP/ICE relay, opaque

// Server → Client
type S2C =
  | { type: 'room-created'; code: string; cameraToken: string; peerId: string }
  | { type: 'room-joined'; peerId: string; cameraPresent: boolean }
  | { type: 'peer-joined'; peerId: string }        // to camera, per viewer
  | { type: 'peer-left'; peerId: string }
  | { type: 'camera-back' }                        // to viewers on re-claim/re-create
  | { type: 'room-closed' }
  | { type: 'signal'; from: string; payload: unknown }
  | { type: 'error'; reason: 'bad-code' | 'room-full' | 'rate-limited' | 'bad-token' | 'invalid' };
```

Hand-rolled validators (no dep): `parseMessage(raw: string, direction: 'c2s' | 's2c'): C2S | S2C | null`. Export `generateCode()` (8 chars, `crypto.getRandomValues`, unambiguous alphabet `ABCDEFGHJKMNPQRSTUVWXYZ23456789`) and `generateToken()` (32 hex chars).
- [ ] **Step 4:** `bun test shared/` → PASS.
- [ ] **Step 5:** Commit `feat: shared signaling protocol with validation`.

### Task 3: Room lifecycle state machine `[core]`

**Files:** Create `server/rooms.ts`, `server/rooms.test.ts`

Pure logic, injectable clock (`now: () => number` passed to constructor). This encodes the spec's room-lifecycle policy exactly — the part the spec review fought over, so tests mirror spec sentences.

- [ ] **Step 1: Write failing tests** for `RoomManager`:
  - `createRoom()` → `{code, cameraToken}`; codes unique; camera marked present.
  - `joinRoom(code)` → viewer id; unknown code → `'bad-code'`; 4th viewer → `'room-full'` (hard cap 3).
  - `cameraDisconnected(code)` → room enters orphaned state; viewers still listed; `isOrphaned(code)` true.
  - `reclaimRoom(code, token)` within 10 min → success, camera present again; wrong token → `'bad-token'`.
  - Grace expiry: advance injected clock 10 min + tick → room destroyed, `joinRoom` now `'bad-code'`.
  - `stopCamera(code, token)` → immediate destroy.
  - `recreateRoom(code)` when room doesn't exist → new room with that code, **fresh** token; when room exists → `'bad-code'` (can't hijack a live room).
  - New viewers MAY join an orphaned room (decided: yes — grandparent opening the link during a blip should not be locked out; they see the DOWN state).
  - Rate limiting: > 10 failed joins from one connection id within 60 s → `'rate-limited'`.
- [ ] **Step 2:** `bun test server/rooms.test.ts` → FAIL.
- [ ] **Step 3:** Implement `RoomManager` (Map-based, no I/O, no timers of its own — expose `sweep()` called by the server on an interval).
- [ ] **Step 4:** `bun test` → PASS.
- [ ] **Step 5:** Commit `feat: room lifecycle state machine per spec`.
